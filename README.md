# Deep-Koopman-KANDy

## Introduction

The introduction to this README is plainly written by a human to detail the experimental procedures and the ideas of
our method and how we came to our conclusions. We pruposley include all experiments in this repository rather

Later sections of this README are generated by an LLM that detail the code structure. 

This repository contains the scientific code and worklflow for the paper:

Deep-Koopman-KANDy: Dictionary Discovery for Deep-Koopman Operators with Kolmogorov-Arnold Networks for Dynamics

by Kevin Slote, Erik Bollt, and Jeremie Fish 
Clarkson Center for Complex Systems Science
Clarkson University
Postdam, NY, USA

This software repository contains at a top level the code needed to reproduce and run the Deep-Koopman-KANDy algorithm

The software experiments were written with Claude Opus 2.6. The agent memory is included ad the code was verified and 
ran indepedenty.

We include all of the experiments that follow a narrative arc of how our algorithm was developed. The first pass
of analysis included the development of the stable propogator. The code in the experiments directory with naming
conventions containing `stable`, `unitary`, or `ergodic`, correspond to an experiment testing which contraint on
the Koopman operator `K`, yeilded the best results.

Proceeding along the narative arc of how we arrived at our conclusions, we tested for model perormance and network
sparcisty eventually arriving at our bet pykan backend model `lorenz_5d_third_test.py`. Then we began testing across
random seeds and different ics

We then began testing against the SINDy-ae method as this was the closed model to our and given the lack of a coherent
similar benchmark of `dictionary extraction` and we used symbolic regression to test the quality of the learned 
autoencoders.

We include numerous experiments detailing the optimal level-set-manifold extraction of the non-linear activations.
Althought, the KANDy model was yeilding better results for some types of functions. This full analysis was mostly 
omitted from the paper.

The mathematics of our method were developed and put as readme files in the `research_materials` directory.

The code that produced the tables and figures in the paper are as follows

Run every command from the repository root. Scripts in `experiments/` that are not listed below are development
experiments and are not needed to reproduce the paper. Tables and figures use the numbering in the camera-ready PDF.

latent-decay analysis. To evaluate its saved model, pass `--skip-train --epochs 200`; the default of 150 epochs does not
match the saved loss history and the loss plot fails.

Table 6 trains any size without a checkpoint in `results/table_6/` and never replaces an existing one. To train only the
two small sizes and reuse the saved large model:

```bash
python experiments/table_6.py --arch 4,16,32 4,32,64
cp results/cat_map_standard/cat_map_model.pt results/table_6/model_4_24_1024.pt
python experiments/table_6.py
```

The horizon in Table 6 is the number of steps before angular MSE reaches 0.03. The epoch count for `[4,32,64]` was not
recorded; `table_6.py` uses 150.

Table 17 needs `results/ks_stable/ks_data.pt` and the saved Mackey-Glass data in `results/mackey_glass/`. It also needs
[PyResDMD](https://github.com/GeorgeCoote/pyresdmd), which is not on PyPI.
